# Third-party notices

This package's own sources do not vendor third-party code. The dependencies below are the prebuilt `libgit2` xcframework declared in `Package.swift`, the libraries that xcframework statically contains, and the system libraries `Package.swift` and the README link.

Checked on 2026-11-05:

- `Package.swift` binary target `libgit2`, URL `https://github.com/light-tech/LibGit2-On-iOS/releases/download/v1.3.1/libgit2.xcframework.zip`, checksum `332bfb255649f2295d5530e4abed4e81803acdc6abf18a266695fdb447ca3df2`. The downloaded zip matches that checksum.
- The zip is dated 2022-07-06. Slices: `ios-arm64`, `ios-arm64_x86_64-simulator`, `ios-arm64_x86_64-maccatalyst`. It contains no COPYING file of its own.
- `ios-arm64/libgit2.a` archive member names, plus `Headers/git2/version.h`, `Headers/openssl/opensslv.h`, `Headers/libssh2.h`, and `Headers/pcre.h`.
- Build script and README at [light-tech/LibGit2-On-iOS](https://github.com/light-tech/LibGit2-On-iOS) tag `v1.3.1`. That README says the scripts are public domain and that "the usage of the result library built by our script is still subjected to `libgit2`, `pcre`, `openssl` and `libssh2` license." Those scripts are not in this repository.
- libgit2 tag `v1.3.1` `COPYING`, `CMakeLists.txt`, and `deps/`.

`LICENSE` in this repository reproduces [libgit2 COPYING on `main`](https://github.com/libgit2/libgit2/blob/main/COPYING), because upstream MiniGit says the project is "Same as libgit2" and links the libgit2 repository without a version. That file is not byte-identical to [COPYING at libgit2 v1.3.1](https://github.com/libgit2/libgit2/blob/v1.3.1/COPYING). The notes below follow the 1.3.1 sources and the binary that this package downloads. `main`'s COPYING adds later notices (PCRE2, llhttp, and others) that this 1.3.1 binary does not ship.

Symbol tables inside the Mach-O objects were not read (host `nm` does not decode them). Identification of objects is by archive member name.

## Unverified or not a single license

- **libiconv.** The linked binary is the operating-system library, and this package does not pin an SDK version beyond iOS 14 and macOS 11. Apple's published sources changed license. Tag `libiconv-64` (imported 2022-09-30) has `OpenSourceLicense` `LGPL`, `OpenSourceVersion` `1.11`, and `OpenSourceURL` `http://ftp.gnu.org/pub/gnu/libiconv/libiconv-1.11.tar.gz`, with `COPYING.LIB` in the tree (https://github.com/apple-oss-distributions/libiconv/tree/libiconv-64). Tag `libiconv-99` (imported 2024-03-26) is a different tree whose `libiconv.txt` states BSD-2-Clause, BSD-3-Clause, and BSD-2-Clause-FreeBSD (https://github.com/apple-oss-distributions/libiconv/blob/libiconv-99/libiconv.txt). Which of those a given app build links was not determined.
- **Whether libgit2 calls the bundled PCRE.** PCRE 8.45 is present in the archive because the LibGit2-On-iOS script merges every static library in the install prefix. libgit2's CMake, when `REGEX_BACKEND` is empty, prefers `regcomp_l` if that symbol exists. On Apple that can select the system regex instead of PCRE. The PCRE license still applies to the objects shipped in the xcframework. Which backend the libgit2 objects in this zip were compiled to call was not confirmed from symbols.
- **PCRE git revision used by the build script.** The script clones `https://github.com/light-tech/PCRE.git` with no commit pin (the directory is named `pcre-8.45`). The headers inside the published zip identify PCRE 8.45, dated 2021-06-15, so the shipped headers are that release. The exact git commit that was cloned on 2022-07-06 was not recorded in this repository.
- **libgit2 COPYING versus `deps/regex`.** v1.3.1 COPYING says "The regex library (`deps/regex/`) is licensed under the GNU LGPL." Tag v1.3.1 has `deps/pcre`, not `deps/regex`. `deps/pcre/COPYING` only says "Please see the file LICENCE in the PCRE distribution" and does not include that licence. The xcframework's PCRE license used above is the BSD text in the shipped `pcre.h`, not that LGPL notice.
- **ntlmclient `LICENSE.txt`.** Headers say third-party copyright information is in `LICENSE.txt`. That file is not in libgit2 v1.3.1 `deps/ntlmclient`. The upstream MIT text was taken from https://github.com/ethomson/ntlmclient/blob/main/LICENSE.txt, which does not list further third-party copyrights. No separate copyright banner was found in `unicode_builtin.c` beyond Edward Thomson's MIT header, and the iOS archive contains `unicode_iconv.c.o` rather than a `unicode_builtin` object. Any additional third-party claims inside ntlmclient that were only in the missing `LICENSE.txt` are unverified.
- **LibXDiff and the linking exception.** `src/xdiff/xdiff.h` is LGPL-2.1-or-later. libgit2's COPYING states the library license as GPL-2.0 with a linking exception and does not say how that interacts with this LGPL header. This notice does not resolve that.
- **SHA-1 collision-detection objects.** `sha1.c.o` and `ubc_check.c.o` match the filenames of the MIT code described in COPYING. The object bytes were not compared with upstream.
- **`winhttp.c.o`.** libgit2 COPYING licenses `deps/winhttp` under LGPL-2.1-or-later for the MinGW import library. The iOS archive has a single `winhttp.c.o`, which is also the filename of libgit2's own transport source. No separate winhttp import-library members were found. Whether that object contains any of the LGPL `deps/winhttp` code was not checked at symbol level.
- **Clar.** COPYING licenses the Clar test framework under the ISC license (Copyright (c) 2011-2015 Vicent Marti). The build script passes `-DBUILD_CLAR=NO`. No Clar archive members were identified. It is not treated as bundled.
- **libgit2's vendored zlib.** `deps/zlib/COPYING` at v1.3.1 is the zlib license, Copyright (C) 1995-2017 Jean-loup Gailly and Mark Adler. Those sources were not compiled into this xcframework (see above). The system libz is what this package links.
- **Sample code copied into MiniGit.** The MiniGit README says "Most functionalities are implemented by literally copy and paste libgit2's sample codes." libgit2 v1.3.1's README says the example code is public domain and points at `examples/COPYING`, which is CC0-1.0. This tree does not include that file, source files are not marked CC0, and the pasted lines were not matched one-for-one. Which parts of `Sources/` are those samples is unverified. Upstream's project-level statement remains "Same as libgit2," which is the license in `LICENSE`.
- **MiniGit copyright holder.** Upstream has no AUTHORS file and no copyright line. The name used in headers is "Lightech", and the GitHub account is `light-tech`. No other copyright holder is stated.
